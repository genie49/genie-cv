# Heirloom — 박물관 유물 관리·AI 분류 시스템

한양대학교 박물관과 협업하여, 유물 사진을 올리면 전처리와 AI 분류 추천을 거쳐 데이터베이스로 쌓이는 유물 관리 시스템.

## 프로젝트 개요

박물관이 소장한 유물을 연구에 활용하려면 사진과 분류 정보가 체계적인 데이터베이스로 정리되어 있어야 합니다. Heirloom은 파편까지 포함한 근대 도자기류 유물을 대상으로, 사진 업로드부터 전처리, AI 분류 추천, 학예사의 확인과 등록까지를 하나의 흐름으로 잇는 시스템입니다. 김형진은 팀에서 인프라와 AI, 프론트엔드를 맡았습니다.

## 기술 스택

- **프론트엔드**: Next.js (App Router), React, TypeScript, Tailwind CSS, Drizzle ORM
- **AI 서버**: FastAPI, LangChain, Gemini (멀티모달), SSE 스트리밍
- **이미지 전처리**: FastAPI, OpenCV, rembg, OWLv2 + SAM
- **데이터**: PostgreSQL, Redis, AWS S3
- **인프라**: k3s, Kustomize, Traefik, Terraform, GitHub Actions
- **관측**: Loki, Grafana, 요청 단위 wide event 로그

## 주요 기능

### 유물·상자 관리

올린 사진은 이미지 그룹으로 묶이고, 학예사는 이를 상자 단위로 분류한 뒤 유물로 등록합니다. 많은 양을 한 번에 다룰 수 있도록 분류 보드에서 드래그 정렬과 일괄 배정을 지원하고, 검색·즐겨찾기·라벨로 다시 찾을 수 있습니다. 기종, 생산지, 기법, 마크, 문양 같은 참조 데이터도 화면에서 직접 관리합니다.

### 서버 이미지 전처리

업로드된 사진은 전처리 서비스가 비동기로 처리합니다. 배경과 그림자, 사진에 함께 찍힌 손을 제거하고, 기준자를 검출해 사진마다 실제 크기 기준을 계산합니다. 작업은 동시성 제한 아래에서 원자적으로 선점되고, 중간에 유실된 작업은 복구 스윕이 되살립니다.

### AI 분류 추천

유물 사진과 참조 데이터를 멀티모달 모델에 전달해 재질·생산지·기종·문양 같은 분류 항목과 마크 코드를 추천합니다. 추천은 그대로 저장되지 않고, 학예사가 확인하고 고친 뒤 등록합니다. 대화 내용을 유지하는 채팅형 에이전트 화면도 함께 제공합니다.

### 자체 운영 클러스터

관리형 서비스 위에서 출발한 구성을 자체 k3s 클러스터로 옮겼습니다. 개발·운영 환경을 한 클러스터에서 분리해 운영하고, GPU가 필요한 전처리 서비스의 스케줄링, 브랜치 머지 시 자동 배포, 데이터베이스 백업과 복구 절차, 로그 수집과 알림까지 직접 구성했습니다.

### 3D 복원을 위한 기반

디지털 복원 단계로 이어질 수 있도록, 이미지 그룹의 기준자와 촬영 정보를 3D 재구성 도구가 읽을 수 있는 형식으로 내보내는 기능까지 마련했습니다. 3D 재구성 자체는 이 시스템 밖의 후속 단계입니다.
